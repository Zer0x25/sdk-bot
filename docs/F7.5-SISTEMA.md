# F7.5 — Sistema

## Resultado

La ruta `/inbox/system` reemplaza el placeholder React con diagnóstico operativo,
logs en vivo de Gateway/Brain, consola administrativa y acciones de mantenimiento.
La vista consulta estado cada 10 segundos, limita el historial de logs en memoria,
permite filtrar niveles, pausar/reanudar el stream y limpiar con confirmación solo
el archivo activo. Los comandos se ejecutan mediante el manejador administrativo
existente; el panel no ofrece una shell del sistema operativo.

La ruta requiere `admin:write` antes de solicitar diagnóstico detallado, abrir SSE
o llamar endpoints legacy. Las sesiones de solo lectura reciben únicamente la
sesión y un mensaje de permiso requerido. La protección backend de `admin:write`
introducida en F7.3 continúa siendo la autoridad.

Se conservan las acciones existentes para iniciar Brain, pausar/reanudar el bot,
reiniciar Gateway y borrar solo la sesión de WhatsApp. El reset limpio mantiene la
confirmación inicial, los 10 segundos de lectura, la escritura de `BORRAR-TODO`
durante 60 segundos y la petición única `{confirm:true, clean:true}`. Se informa
qué estado se elimina y que los perfiles Markdown sobreviven. Si el resultado de
una operación destructiva es incierto, la UI bloquea otro intento hasta revisar el
estado del sistema.

La navegación móvil incorpora Sistema y la vista se adapta a una columna. Cuando
el navegador no ofrece `EventSource`, el diagnóstico y las demás acciones siguen
disponibles y los logs muestran esa limitación.

## Verificación

- Prueba enfocada `SystemPage.test.tsx`: 8 casos pasan con API/EventSource simulados.
- `cd gateway && npm run check`: ESLint, typecheck Gateway/React, 38 pruebas React,
  build Vite, montaje bajo `/inbox` y 320 pruebas Gateway pasan.
- `git diff --check` pasa.

Las pruebas verifican la frontera de permisos, los diagnósticos y Brain, una sola
ejecución por comando, ciclo de vida SSE/filtros, confirmación de limpieza de logs,
reset de sesión, los temporizadores y palabra exacta del reset limpio, y reinicio
de Gateway. No se inició Brain/Gateway, no se invocaron comandos administrativos
reales ni se borraron logs, sesiones o datos.

## Límites

- El estado y mantenimiento siguen usando los endpoints legacy existentes, que
  están protegidos por `admin:write`; no se añadieron rutas ni contratos nuevos.
- La UI no configura Telegram ni envía mensajes de prueba. Campañas permanecen
  fuera de esta pantalla hasta que exista un flujo completo de operación.
- F7.6 debe inventariar toda la paridad del panel anterior y decidir qué se retira.
- No se hizo push ni despliegue.
