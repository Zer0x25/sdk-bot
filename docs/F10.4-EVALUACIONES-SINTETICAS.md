# F10.4 — Evaluaciones sintéticas de asistencia — 2026-10-22

**Estado:** implementado y verificado localmente el 2026-10-22. No publicado.

## Casos

- **Control humano:** preparar asistencia con `automationMode=human`; el archivo,
  la secuencia y la bandeja de salida deben quedar intactos.
- **Borrador frente a entrega:** la salida se etiqueta como borrador de respuesta,
  no se persiste como mensaje ni como nota, y no crea una intención outbound.
- **Aislamiento entre cuentas:** el segundo hilo de otra cuenta contiene un dato
  sintético secreto; búsqueda y citas de la conversación seleccionada no pueden
  devolverlo. Un intento de citar directamente el mensaje externo se rechaza.
- **Límites de evidencia:** ante una consulta sintética sin precio ni destino en el
  historial, Brain recibe instrucciones para no inventar el dato y pedirlo en el
  borrador. El caso entrega una respuesta controlada que reconoce la falta.

Gateway ejecuta los tres primeros casos contra SQLite temporal y la ruta real de
asistencia, con Brain reemplazado por respuestas deterministas. Brain ejecuta el
cuarto contra su endpoint real con el proveedor sustituido. No se simula un segundo
motor de permisos ni se conecta un proveedor o canal real.

## Verificación y límites

La suite demuestra el aislamiento del contexto, el rechazo de referencias foráneas,
que preparar resumen/borrador no equivale a enviar, y que el prompt de Brain pide
reconocer datos ausentes. No mide si un modelo externo seguirá esas instrucciones,
ni prueba calidad factual estadística; esa evaluación requiere un proveedor/modelo
definido y un conjunto versionado de respuestas esperadas.

- `npm run check` (raíz): contratos 19/19, generación sincronizada y typecheck.
- `cd apps/gateway && npm run check`: lint/typecheck, panel 42/42, build Vite,
  integración del build 1/1 y Gateway 359/359.
- `cd apps/brain && ../../brain/venv/bin/ruff check . && ../../brain/venv/bin/python
  -m pytest tests/ -q`: Ruff limpio y 35/35 tests.

  tras un fallo transitorio de captura de logs en una ejecución concurrente.
