# F4.1 — Shell visual de la bandeja

Actualización: 2026-10-20. Primera unidad de UI de Fase 4; no conecta todavía el
archivo de conversaciones.

## Resultado

- La app React/TypeScript/Vite vive en `gateway/panel/web`; React Router conserva
  `conversationId` en la ruta. El shell tiene navegación lateral, bandeja, hilo,
  ficha contextual, tokens visuales y CSS responsive para escritorio y móvil.
- El estado vacío explica que el historial se conectará después y no presenta chats
  ni mensajes ficticios. El compositor y las búsquedas/filtros se muestran como
  vistas previas deshabilitadas.
- El bundle se sirve en `/inbox` por el proceso actual del panel. Requiere
  `PANEL_CONVERSATIONS_UI_ENABLED=true`, después de la frontera OAuth existente;
  apagado por defecto, `/` sigue sirviendo el panel previo.
- Docker construye Vite en una etapa con dependencias de desarrollo y copia solo el
  artefacto a la etapa runtime. El proceso del panel no abre otra sesión de canal.

## Verificación

- `cd gateway && npm ci`: instalación limpia desde el lockfile.
- `cd gateway && npm run check`: ESLint, TypeScript gateway y UI, Vitest, build Vite,
  prueba HTTP del artefacto servido y suite gateway. En Node 24.19/Linux: 3 pruebas
  Vitest y 269 pruebas Node pasan.
- La prueba UI confirma regiones/semántica accesibles, navegación activa, foco por
  teclado al enlace para saltar al contenido y ausencia de datos inventados.
- La prueba HTTP confirma feature flag, ruta SPA, assets servidos, `/inbox` anidada,
  fallback de rutas y límites de traversal; pruebas de frontera conservan OAuth y
  `/` anterior.
- Build de producción probado con `deploy/docker/gateway.Dockerfile` sobre Node 22;
  prueba del runtime confirma bundle y contratos presentes, sin Vite instalado.
  El CA de este entorno se montó como secreto BuildKit solo durante `npm ci` y no
  queda almacenado en capas.

## Límites y siguiente unidad

No se conectan todavía lista, historial, búsqueda/filtros funcionales, SSE ni datos
de contacto; tampoco se habilita envío ni control humano. La verificación de
responsividad en esta unidad combina CSS por viewport con pruebas de componente,
sin una pasada E2E/renderizada en navegador real. F4.2 conecta lista, selección,
detalle e historial paginado a la API real; F4.3 agrega SSE, reconexión y resync.
