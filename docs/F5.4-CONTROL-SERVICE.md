# F5.4 — Servicio compartido y corte de control

## Dominio y autoridad

`ControlService` es la entrada común para takeover, release, lifecycle, acceso,
perfiles y política global. La API autenticada obtiene el actor de la firma del
gateway; los comandos heredados usan el actor técnico local. Las escrituras usan
`expectedVersion`, conservan el actor de auditoría y cambian control/evento dentro
de una transacción SQLite.

Los comandos que reciben un teléfono o ID resuelven coincidencias exactas por
canal y cuenta. Sin una cuenta, varias conversaciones posibles producen
`IDENTITY_AMBIGUOUS`; nunca se elige una coincidencia por subcadena de dígitos.
La proyección de mensajes consulta la identidad exacta y falla cerrada si la
autoridad SQLite no puede leerse o no encuentra una conversación.

Un takeover crea una operación con clave idempotente y deja la conversación en
`taking_control` antes de drenar. La confirmación espera a que los buffers se
reconozcan durablemente y que termine el trabajo activo. Si el proceso reinicia,
el gateway vuelve a cargar las operaciones pendientes antes de habilitar el
servicio. La conversación permanece en modo humano durante el proceso; la salida
anterior no se vuelve a lanzar.

## Esquema y corte

La migración v6→v7 rehace `events` para permitir auditoría de política global sin
conversación, conserva la línea de eventos y crea `control_operations`. Las bases
nuevas y las migraciones v5/v6 reportan v7 una vez abiertas.

El gateway crea el servicio, sincroniza la política activa, recupera operaciones
pendientes y registra readiness. El corte solo acepta staging verificado y cambia
la autoridad al final de la aplicación transaccional por lotes. La aceptación se
ejecutó sobre SQLite temporal. No se abrió el archivo runtime ni se migraron sus
contactos/settings; la CLI mantiene sus puertas de lock y validación de fuentes.

La política global `allowed_all` permite la IA para controles neutrales; `ignored_all`
la bloquea. Los controles permitidos explícitamente conservan su preferencia. Una
conversación cerrada, excluida o marcada para revisión permanece bloqueada.

## Problema no bloqueante registrado

BUG-071: `/ignorar contactos de agenda` puede exagerar el total informado con
registros duplicados o conversaciones que ya estaban ignoradas. El cambio de
control se mantiene correcto; queda anotado para una unidad posterior.
