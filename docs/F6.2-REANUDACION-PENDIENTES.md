# F6.2 — Selección explícita de entradas al devolver el control

Actualización: 2026-10-20. F6.2 agrega una política explícita para liberar el
control humano: automatizar solo entradas futuras o elegir entradas recientes
concretas para que la IA las procese. F6 sigue abierta para el recorrido E2E y el
smoke con una cuenta de prueba.

## Cambios

- SQLite migra de v9 a v10 y guarda el último `inbound_seq` atendido y el corte de
  reanudación. Las bases existentes inicializan ambos valores al watermark actual.
- `future_only` omite despachos pendientes anteriores al corte y bloquea el inicio
  tardío de automatización para mensajes antiguos que ya estaban en memoria.
- La API autenticada muestra entradas live de las últimas 24 horas con contenido
  procesable, secuencia y vista previa. La interfaz permite seleccionar IDs
  explícitamente; las entradas antiguas no elegidas permanecen en el historial.
- El servidor revalida control, política, IDs y huella del contenido dentro de la
  transacción del release. La huella queda obsoleta si cambian la selección, el
  contenido, el contexto o la política.
- Un intent humano o IA que sigue `sending` o `delivery_unknown` impide
  `process_pending`. La opción `future_only` sigue disponible. Los despachos aún
  pendientes/en espera y el contenido sin texto procesable aparecen como exclusiones.
- La aceptación durable de una respuesta humana o IA adelanta el watermark usando
  la secuencia declarada por el hilo o los IDs de entrada que originaron la respuesta.
