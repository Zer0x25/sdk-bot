# F3.1 — Lectura autenticada de conversaciones

Actualización: 2026-10-20. Contratos: [schema v1](../packages/contracts/schema.json)
y [OpenAPI](../packages/contracts/openapi.json). Fuente del plan:
[ROADMAP](ROADMAP.md), estado: [SESSION-STATE](SESSION-STATE.md).

## Entrega

El gateway expone bajo la sesión firmada:

| Ruta | Resultado |
|---|---|
| `GET /v1/accounts` | Cuentas sin `providerKey`, capacidades y estado del adaptador ligado a esa cuenta. |
| `GET /v1/conversations` | Página por actividad/id, filtros por canal/cuenta/control/ciclo/no leídos/nombre. |
| `GET /v1/conversations/:id` | Control proyectado, cobertura, no leídos, capacidades y watermark. |
| `GET /v1/conversations/:id/messages` | Mensajes en orden cronológico estable y página anterior por `(occurredAt,id)`. |
| `POST /v1/conversations/:id/read` | Avanza monotónicamente el cursor entrante local del actor. |

El panel valida cada respuesta contra su contrato v1. Las consultas rechazan
parámetros desconocidos, duplicados, coerciones y límites fuera de 1–100. El cursor
es opaco y HMAC con el secreto de frontera; se liga a actor, filtros, época,
watermark y revisiones de la agenda/política/lecturas. Si la lista cambia mientras
se pagina, responde `410 CURSOR_EXPIRED`; restaurar otra época responde
`409 DATA_EPOCH_MISMATCH`.

## Proyecciones y privacidad

Los nombres de contacto se resuelven solo por una identidad WhatsApp exacta. Si no
hay coincidencia inequívoca, `displayName` es null. La búsqueda cubre el nombre,
no texto de mensajes ni números. Las respuestas no exponen JID/LID/teléfono,
`providerKey`, rutas locales ni payloads internos.

Hasta F5, accessPolicy/automationMode son una proyección de la agenda/settings
heredados; `controlVersion` y `contextVersion` comienzan en `1` y no habilitan
mutaciones de control. `historyCoverage.capturingSince` puede ser null, y ningún
valor certifica que el proveedor haya entregado una conversación completa.

SQLite v4 agrega `read_cursors`, con clave actor/conversación y avance decimal sin
coerción a Number. El contador incluye solo mensajes entrantes posteriores al
cursor de ese actor. No envía recibos de lectura de WhatsApp/Telegram y sobrevive
al reinicio del gateway.

## Evidencia

Comandos ejecutados en Node 24.19.0/Linux:

- Raíz `npm run check`: generación de contratos, typecheck y 15 pruebas aprobadas.
- `gateway/npm run check`: lint, typecheck y 258 pruebas aprobadas.
- Prueba HTTP de API con firma: filtros y nombres, protección de texto/IDs, empate
  de timestamps, cursores HMAC y por actor, capacidades, cobertura parcial, cuentas,
  reanudación de mensajes, lecturas monotónicas y durables, y límites 401/403/410/422.

BUG-056 y BUG-057 se reprodujeron durante la implementación, bloquearon la lectura
filtrada y quedaron corregidos con regresiones en la suite. BUG-024 continúa siendo
puerta antes de dar acceso a operadores con grants limitados. SSE/replay/resync sigue
en F3.2; esta entrega no agrega UI ni takeover.
