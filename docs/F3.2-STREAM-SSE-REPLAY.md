# F3.2 — SSE autenticado, replay y resincronización

La API interna `GET /v1/events` ahora transmite invalidaciones mínimas desde el
archivo SQLite. Cada `data:` contiene un `Event` validado con cursor
`dataEpoch:seq`; no transmite texto ni cuerpos de mensajes. El worker publica
solo después del commit de `ingestBatch`, captura Telegram y actualización de
transcripción.

El gateway registra el listener antes de capturar el watermark. Al reanudar,
consulta páginas durables acotadas hasta ese watermark y después drena la cola
viva, descartando secuencias ya reproducidas. La prueba induce una escritura
después de capturar el watermark y antes de comenzar el replay; los cuatro
eventos llegan una sola vez y ordenados. Un hueco en la retención —incluida la
purga por antigüedad— o un cambio de época produce `resync.required` con el
watermark actual. El archivo sigue reteniendo exactamente su ventana configurada;
la API no amplía el log para favorecer conexiones antiguas.

Una conexión nueva sin `Last-Event-ID` recibe un frame id-only con el watermark
actual y el cliente carga el snapshot después de abrir el stream. El checkpoint
permite que `EventSource` reanude aunque todavía no haya llegado un evento de
dominio. Las líneas con `data` siempre llevan el `id`, `event` y JSON de contrato.
El proxy conserva `Last-Event-ID`, transmite `text/event-stream` y cierra el
upstream cuando el navegador desconecta.

El stream respeta el grant firmado de 30 segundos: termina al expirar el contexto
del gateway y el cliente se reconecta para volver a validar actor/capacidad. El
proxy también limita la conexión al vencimiento de la sesión web. Los recursos
por suscriptor están acotados a 1.000 eventos o 1 MiB; ante saturación se cierra
la conexión para que el cursor durable gobierne el replay. Hay heartbeat cada 15
segundos y `retry: 3000`.

## Evidencia

- `gateway npm run check`: lint, TypeScript y 264 pruebas pasan en Node 24.19.0,
  Linux. Incluye publicación tras commit, duplicado silencioso, replay/live sin
  huecos ni duplicados, checkpoint inicial, expiración, cambio de época,
  autorización, errores sanitizados, proxy y desconexión.
- `npm run check` raíz: generación de contratos, TypeScript y 15 pruebas pasan.
- El proxy ya cubría timeout de gateway no disponible; la prueba nueva confirma
  que `Last-Event-ID` llega a `/v1/events` y que cancelar el body cierra el socket
  upstream.
- No se encontraron defectos funcionales nuevos en esta unidad. BUG-024 sigue
  abierto como puerta para grants de operadores limitados; no se agregó UI ni
  takeover.

La bandeja F4 debe consumir el checkpoint, cargar snapshot después de abrir el SSE,
aplicar invalidaciones a caché sin reconstruir todo el hilo y reintentar con el
último cursor. No se validaron canales reales ni una cuenta de navegador real.
