# F6.1 — Control humano y envío desde el hilo

Actualización: 2026-10-20. Implementación del flujo inicial del panel sobre el
archivo SQLite y el outbox ya existentes. F6 sigue abierta hasta completar la
selección de pendientes, el recorrido E2E y el smoke con cuenta de prueba.

## Cambios

- El hilo muestra toma/devolución de control, resolución/reapertura y el estado
  `taking_control`. El compositor requiere permiso `messages:send`, canal conectado
  con capacidad de respuesta, conversación abierta y control humano confirmado;
  también comprueba propietario o permiso de override.
- `POST /messages` toma la identidad canónica exacta del archivo. El servidor exige
  una captura vigente de control/contexto/política y crea una clave de outbox a
  partir de actor, conversación y `clientMessageId`. El worker vuelve a validar
  propietario y estado en la transacción que reclama el envío.
- Una liberación, reasignación o resolución no cruza un envío humano ya reclamado.
  Si el intento está incierto, no se reenvía automáticamente.
- Al confirmar el proveedor, el worker enlaza el mensaje del canal con el actor y
  `clientMessageId`, incluyendo el caso donde el eco del canal se archivó primero.
  La atribución publica `message.updated` para las otras sesiones. La respuesta 202
  devuelve el ID del mensaje archivado.
- El panel presenta el mensaje de forma optimista. Los fallos conservan el borrador;
  ante una respuesta perdida o entrega incierta se informa el posible duplicado y
  se exige confirmación para crear un nuevo envío. La incertidumbre se conserva por
  conversación y se limpia al reconciliar el mensaje archivado. Un intent que aún
  está `sending` consulta la misma clave durable; no crea otro envío. Telegram recibe
  texto sin modo Markdown implícito.
- Se ampliaron los códigos de `ErrorResponse` para que la frontera autenticada
  pueda serializar conflictos y errores de control/envío sin invalidar la respuesta.

## Comprobaciones y pendientes

- `cd gateway && npm run lint`: limpio.
- `cd gateway && npm run typecheck`: limpio.
- `cd gateway && npm run panel:typecheck`: limpio.
- No se ejecutó una suite de pruebas en esta entrega. F6.3 verificará el recorrido
  con proveedores falsos y el siguiente mensaje IA con contexto humano.
- `release` conserva `future_only`; F6.2 añadirá la elección explícita para procesar
  entradas pendientes. No se usó una cuenta real ni se ejecutó un reset.
