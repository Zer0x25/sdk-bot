# F9.3 — Búsqueda de contenido con FTS5

## Alcance implementado

- La migración SQLite v13 crea `message_search` con FTS5 y tokenizer
  `unicode61 remove_diacritics 2`, rellena mensajes existentes y mantiene el
  índice por triggers al insertar, editar, completar una transcripción, revocar
  o purgar un mensaje.
- Solo indexa texto, captions y transcripciones, con un máximo de 16.384
  caracteres por mensaje. Los cuerpos oversized y los mensajes borrados quedan
  fuera; los binarios no se indexan.
- `GET /v1/conversations/{conversationId}/search` exige `conversations:read` y
  valida que el actor pueda ver el hilo. La consulta se convierte en hasta 32
  términos Unicode literales unidos con `AND`; la entrada nunca se ejecuta como
  sintaxis FTS.
- La API devuelve mensajes y snippets de texto plano, en orden estable por
  `(occurredAt,id)` descendente. El cursor HMAC está ligado al actor, hilo,
  términos, límite y snapshot `{dataEpoch,seq}`. El worker verifica ese snapshot
  dentro de la misma operación SQLite que lee la página. Si cambia cualquier
  secuencia del archivo, devuelve `CURSOR_EXPIRED` y la interfaz reinicia la
  búsqueda desde la primera página.
- La bandeja permite abrir la búsqueda del hilo actual, ver snippets y pedir
  más resultados. React inserta el snippet como texto, nunca como HTML.
- El modo read-only acepta archivos v13. Las pruebas de backup/restauración de
  F9.4 deben confirmar la continuidad entre este índice, el ledger y los blobs.
