# F9.4 — Backup y restauración de ledger, blobs e índice FTS

## Alcance implementado

- La puerta `conversations:restore-check` sigue siendo offline, de solo lectura y
  no promueve/restaura datos. Ahora comprueba el checkpoint/ledger SQLite, la
  integridad referencial, los envíos pendientes, los bytes de cada blob y la
  coherencia del índice FTS5 v13.
- `--snapshot-attachments /ruta/absoluta` permite señalar el directorio de blobs
  del candidato. Por defecto se usa `attachments/` junto a su archivo SQLite.
- El inventario de blobs valida directorio privado `0700`, archivos UUID `.blob`
  regulares con permisos `0600`, tamaños, ausencia de extras y SHA-256/tamaño
  contra cada fila del ledger. Un snapshot con blobs debe residir en un directorio
  físico separado del directorio activo.
- El checkpoint vuelve a calcular las filas FTS esperadas desde mensajes
  elegibles y detecta filas faltantes, sobrantes o divergentes. La puerta exige
  consistencia interna en ambos archivos y paridad del índice entre ellos.
- La extensión SQLite v15 incluye cantidad y digest del inbox administrativo
  Telegram en el checkpoint; el restore-check bloquea diferencias de recibos
  aunque no cambie la secuencia de eventos de clientes. La salida conserva el
  digest oculto y muestra solo el contador/código de bloqueo.
- La prueba integral crea un mensaje multimedia con caption, un blob y su fila
  indexada; crea la DB snapshot con `VACUUM INTO`, copia el directorio de adjuntos,
  verifica la promoción candidata, restaura una copia aislada y consulta FTS y el
  archivo binario restaurado. Después altera por separado el índice y el blob y
  comprueba que cada snapshot queda bloqueado. También comprueba que no se acepte
  el mismo directorio físico de blobs como fuente y candidato.

## Uso operativo

Ejecutar después de detener Gateway, con los archivos SQLite quiescentes y sin
WAL/SHM/journal. El respaldo operativo sigue siendo offline del volumen completo;
la puerta compara la DB de conversaciones y su directorio de blobs, no verifica
la coherencia temporal del resto del volumen ni realiza una recuperación
productiva. Si la fuente activa no está disponible, no puede demostrar paridad:
mantener cualquier restauración en aislamiento y registrar la ventana sin cubrir.

```bash
cd apps/gateway
SDK_CONVERSATIONS_DB_PATH=/ruta/absoluta/activa.db \
SDK_GATEWAY_LOCK_PATH=/ruta/absoluta/gateway/.gateway.lock \
npm run conversations:restore-check -- \
  --snapshot /ruta/absoluta/copia/conversations.db \
  --snapshot-attachments /ruta/absoluta/copia/attachments
```

Código 0 indica que el candidato coincide con la fuente detenida; código 2 bloquea
por diferencia, corrupción o condición de ejecución no segura. La salida expone
contadores y códigos acotados, nunca filas, texto, identidades, rutas ni hashes.
