# F5.2 — Informe dry-run de importación de control

## Uso

Con el gateway detenido y la base ya migrada a SQLite v6, ejecutar desde
`gateway/`:

```bash
npm run conversations:control-dry-run
```

El comando lee `SDK_CONTACTS_DB_PATH`, `SDK_SETTINGS_DB_PATH`,
`SDK_BRAIN_PROFILES_DIR`, `SDK_CONVERSATIONS_DB_PATH` y
`SDK_GATEWAY_LOCK_PATH`; sin overrides usa las rutas del repositorio/runtime.
Imprime el informe JSON en stdout. Exit code 0 significa que el informe no tiene
bloqueos de revisión; exit code 2 indica una fuente, identidad, perfil o regla que
requiere atención. No aplica ninguna migración.

## Informe y mapeo

El manifest incluye SHA-256 de cada JSON, tamaño/nombre de archivo, versión,
`dataEpoch` y secuencia SQLite, y un checksum del inventario de nombres de perfiles.
Cada entrada tiene `sourceKey` seudónimo, checksum canónico del registro y
`targetId` cuando existe. Los hints de identidad solo muestran tipo y últimos cuatro
dígitos; nunca imprime nombre, número/JID completo ni valores de credenciales.
Claves de settings fuera del alcance de control se cuentan, no se listan.

Solo se resuelven los campos `phone` y `lid` contra identidades WhatsApp exactas
del archivo SQLite. Falta de identidad/target, ambigüedad entre cuentas/canales y
reglas distintas sobre el mismo target quedan en cuarentena. Grupos/broadcast
reconocibles se excluyen. Un estado legacy desconocido se importa como neutral,
apagado y con revisión. `handoff` se conserva como human aunque su `handoffAt`
haya vencido; los registros sin perfil disponible quedan apagados y requieren
revisión. Los totales verifican
`sourceRecords = imported + quarantined + excluded`.

El informe marca que la pausa legacy no es persistente y exige mantener IA pausada
durante el futuro corte. El modo global no reconocido cae a `ignored_all` para el
plan y bloquea el corte hasta revisión. Los tokens y demás settings fuera del
módulo permanecen en JSON.

## Solo lectura y límites

El comando rechaza un lock del gateway cuyo PID sigue activo. El worker abre la
base como SQLite `immutable`/read-only; requiere esquema v5 y se niega a abrir si
detecta `-wal`, `-shm` o `-journal`, para no omitir commits WAL ni crear sidecars.
El informe liga su resultado a `dataEpoch`/secuencia. Si hay lock o sidecar, se
debe cerrar normalmente el dueño SQLite y repetir; el dry-run no limpia esos
archivos. Los errores de parsing se reportan por código, sin imprimir contenido.

La prueba de CLI usa JSON/base SQLite temporales y confirma que no cambian los
bytes de las fuentes ni el archivo de datos, y que no aparecen sidecars. No se
ejecutó contra los contactos/settings del entorno ni cambió la autoridad. El
El informe no aplica datos. El staging por lotes, la delta y la recuperación están
descritos en [F5.3](F5.3-STAGING-CUTOVER.md); el corte sigue bloqueado hasta que
F5.4 conecte el servicio compartido.
